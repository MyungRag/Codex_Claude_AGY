# Agent Desk — 프로젝트·기획·개발·검토

Codex · Claude · Antigravity와 함께 기획을 정리하고, 격리된 작업본에서 구현·검토·실행 결과를 관리하는 로컬 대시보드입니다.

## Windows에서 실행

1. Node.js 20 이상을 설치합니다.
2. 저장소를 내려받고 `start-windows.cmd`를 실행합니다. 브라우저가 자동으로 열립니다.
3. 또는 프로젝트 폴더에서 `npm start`를 실행하고 http://127.0.0.1:4173 을 엽니다.

별도 패키지 설치는 필요하지 않습니다. 서버는 기본적으로 해당 PC에서만 접속할 수 있습니다. 창을 닫거나 Ctrl+C로 종료할 수 있습니다.

## v0.9.0 주 AI 통합 · 기본값으로 초안 개발

**AI로 노드 정리**와 **AI로 질문 검토**에서 참여 AI와 주 AI를 각각 선택합니다. 참여한 AI들이 독립적으로 검토한 뒤, 주 AI가 기존 기획·사용자 대화·각 응답을 받아 통합안을 한 번 더 만듭니다. 세 AI가 모두 참여하면 기본적으로 독립 검토 3회 + 주 AI 통합 1회입니다. AI 연결의 모델 설정을 사용하며 이번 검토에만 다른 모델·강도를 지정할 수도 있습니다.

- **노드 정리**: 주 AI가 중복 통합, 이동, 세분화와 여러 단계의 상하위 구조를 정리합니다. 기능의 포함 관계와 실제 구현 선행 조건은 따로 관리합니다. 선택하지 않은 노드·기존 질문 연결을 보존하며, 노드 누락·순환·잘못된 연결은 반영 전에 검사합니다. 깊이를 늘리기 위한 불필요한 세분화는 요구하지 않습니다.
- **질문 통합**: 각 AI의 제안을 기존 질문 ID와 연결해 의미가 같은 질문을 하나로 합칩니다. 원문이 다른 중복의 판단은 주 AI가 하며, 실행기는 기존 질문의 누락·출처 중복·서로 다른 저장 답변의 잘못된 병합을 검사합니다. 새 검토를 반복해도 기존 답변은 유지합니다.
- **선택과 기본값**: 첫 번째 선택지를 무조건 쓰지 않고, 주 AI가 명시한 추천 기본값과 이유를 보여줍니다. **통합안 반영**을 누르면 미답변 설계 선택은 **AI 가정**으로 채택합니다. 객관식 선택·직접 입력·새로운 사용자 대화가 기본값보다 우선하며, 이미 저장한 답변과 명시적 보류를 임의로 덮어쓰지 않습니다. 실제 계정·자료·외부 사실은 지어내지 않고 확인 필요로 남깁니다. 기획 확정 시에도 적용 가능한 미답변 추천값을 채택합니다.
- **추가 요구와 재시도**: 검토 창의 추가 요구를 입력하고 **추가 요구로 다시 통합**을 누르면 원래 응답을 재사용하여 주 AI만 다시 호출합니다. 일부 AI가 실패하면 도착한 응답으로 통합할 수 있고, 통합 실패 시 주 AI를 바꾸거나 다시 요청할 수 있습니다. 실패·취소를 성공으로 표시하지 않습니다.
- **저장과 이전 응답**: 반영 실패 시 입력과 응답을 유지합니다. 이전 버전의 같은 탭에 남은 응답은 **남은 응답을 주 AI로 통합**으로 전환할 수 있습니다. 반영한 통합 검토의 AI별 원문·주 AI·추가 요구는 최근 3건까지 프로젝트에 보관하며 JSON 백업과 되돌리기에 포함됩니다. 입력란에서 답변을 쓴 직후 누른 첫 반영 클릭이 사라지던 이벤트 문제도 수정했습니다.
- **노드별 개발**: 채택한 AI 가정을 업무 분담·Builder·Auditor에 동일한 구현 기준으로 전달합니다. 선행 결정이 해결되면 후속 작업의 대기 조건을 다시 평가합니다. 실제 선행 작업의 검증 실패나 핵심 구현 오류를 무시하고 다음 단계로 넘기지는 않습니다.
- **나중에 수정할 근거**: 실행 버전에 확정 기획·사용자 결정/AI 가정·대안 선택지·관련 노드·변경 파일·검사 결과를 연결해 표시하고, 결과물 ZIP의 `_agent_desk_decisions.json`에도 보관합니다. 현재 기획에서 답변을 바꾸고 새 확정본과 분담안을 만들면 영향받은 작업을 다시 실행할 수 있습니다. 결과 화면에서 선택지만 바꾸어 자동 재개발하는 전용 **수정안 개발** 화면은 이번 범위에 포함하지 않습니다.

### 별도 검사 명령이 없는 프로젝트

기존에 설정한 검사 명령은 그대로 사용합니다. 명령이 비어 있으면 Builder에게 실제 동작을 확인하는 `agent-desk.test.mjs`와 정적 웹의 `agent-desk.checks.json`을 함께 작성하도록 요청하고, 생성된 검사 정의를 격리된 작업본에서 실행합니다.

- `agent-desk.test.mjs`: `node:test`와 `node:assert`를 사용하는 기능 검사입니다. Node.js로 실제 실행하며 자동 검사의 제한 시간은 30초입니다.
- `agent-desk.checks.json`: `{ "checks": [{ "name": "계산 결과", "nodeIds": ["작업-ID"], "steps": [{ "action": "fill", "selector": "#expression", "value": "2+3" }, { "action": "click", "selector": "#calculate" }], "expect": [{ "selector": "#result", "text": "5", "mode": "equals" }] }] }` 형식입니다. `click`, `fill`, `select` 입력과 `equals`, `contains` 결과 비교를 지원합니다. 노드 실행에서는 해당 `nodeIds` 검사, 최종 후보에서는 전체 검사를 실행합니다.
- 화면 검사는 설치된 Chrome 또는 Edge(Linux는 Chromium도 지원)의 별도 임시 프로필을 사용합니다. 브라우저가 없으면 환경 준비 필요로 표시합니다. 검사 파일이 없거나 실행 근거가 부족한 경우 검증된 것으로 간주하지 않습니다.
- 실제 검사 실패나 핵심 오류가 있으면 새 실행 버전을 배포하지 않습니다. 시작 확인만 된 **실행 가능한 초안**과 현재 코드의 기능 검사·독립 검토를 마친 **검토 완료 버전**을 구분해 표시합니다. AI가 생성한 검사의 충분성도 독립 검토 대상이며 모든 버그의 부재를 보증하지 않습니다.

### 기존 프로젝트를 유지하며 교체

1. 기존 실행기 명령창에서 `Ctrl+C`로 종료합니다.
2. v0.9.0 ZIP을 **새 폴더**에 압축 해제하고 `start-windows.cmd`를 실행합니다.
3. 같은 브라우저의 기존 `http://127.0.0.1:4173` 탭에서 `Ctrl+Shift+R`을 누릅니다. 새 검토 창 제목에 **주 AI 통합**이 표시됩니다.

프로젝트나 브라우저 데이터를 삭제할 필요가 없습니다. 미반영 응답은 탭 세션에 있으므로 기존 탭을 사용하세요. 새 코드로 기획을 바꾸더라도 이전 확정본은 불변이며, 새 기본값으로 개발하려면 새 **기획 확정 → 업무 분담안 저장**을 거쳐야 합니다.

전체 자동 테스트 **203개**와 구문 검사를 통과했습니다. 검증 내역은 저장소의 `verification/v0.9.0.md`를 참고하세요. 자동 테스트의 AI 응답은 테스트용 CLI이며, 실제 유료 계정 응답 품질과 Windows 실기기 실행은 별도 확인이 필요합니다.

## 이전 질문·제약의 관련 결정 오류 수정 · 수정판 4

`decision-links-fix4`는 **“충돌 검토의 관련 결정을 확인해 주세요.”** 오류 때문에 선택한 AI 응답 전체가 반영되지 않는 경로를 수정합니다. 일반 질문·추가 확인·제약의 `relatedIds`에 노드 ID나 존재하지 않는 결정 ID가 들어오면, 이전 코드는 실제 충돌 항목과 같은 연결 검사를 적용해 저장을 중단했습니다.

- 일반 질문·추가 확인·제약에는 불필요한 관련 결정 ID를 제거하고 질문 내용·관련 노드·선택지·AI 근거를 반영합니다. 같은 탭에 남아 있는 이전 미반영 응답에도 적용됩니다.
- 기존 확정 답변과 저장된 연결은 유지합니다. 같은 질문을 다시 검토해도 불필요한 연결 차이 때문에 새 질문으로 중복 추가하지 않습니다.
- 새 AI 요청은 질문 검토와 결정 충돌 검토의 응답 형식을 구분합니다. 실제 충돌 항목에는 기존 결정 연결 검증을 유지하며, 연결 오류에는 **AI 이름과 항목 번호**를 표시합니다. 문제가 있는 응답을 제외하고 나머지를 반영할 수 있습니다.

교체 방법: 기존 실행기 명령창을 `Ctrl+C`로 종료하고 새 ZIP을 별도 폴더에 푼 뒤 `start-windows.cmd`를 실행합니다. 기존과 같은 브라우저·주소의 **기존 탭에서 `Ctrl+Shift+R`**을 누릅니다. 검토 창에 **반영 상태 확인 · 연결 오류 수정판 4**가 보이면 새 코드입니다. 프로젝트를 삭제하거나 다시 만들 필요가 없으며, 이미 반영한 두 AI 결과도 유지됩니다. 선택한 응답을 성공적으로 반영하면 해당 검토의 임시 응답은 비워지므로, 제외했던 응답이 남아 있지 않으면 새 검토를 요청하세요.

검증: 자동 테스트 **193개**와 구문 검사를 통과했습니다. Chromium에서 이전 코드로 정확한 오류 문구와 저장 중단을 재현한 뒤, 같은 세 개의 임시 응답을 유지한 채 수정 코드로 반영하여 창 닫힘·3개 항목 저장·기존 확정 답변 보존·새로고침 후 유지를 확인했습니다. 사용자의 실제 세 번째 응답 내용은 확보하지 않았고 Windows 실기기·실제 CLI 계정 호출은 검증하지 않았습니다.

## 이전 진단판 3 안내

`decision-apply-diagnostics3` 패키지는 콘솔 없이 반영이 멈춘 단계를 확인하는 진단판입니다. 실제 PC에서 발생한 문제의 해결 여부는 진단 내용과 해당 환경의 동작을 확인해야 합니다.

1. 기존 실행기 명령창에서 `Ctrl+C`로 종료하고 진단판 폴더의 `start-windows.cmd`를 실행합니다. 기존 프로젝트와 브라우저 데이터는 삭제하지 않습니다.
2. 같은 브라우저의 기존 Agent Desk 탭에서 `Ctrl+Shift+R`로 강력 새로고침합니다. `F5` 또는 `Ctrl+R`은 일반 새로고침입니다. 같은 주소의 프로젝트 저장 데이터는 유지됩니다.
3. **AI로 질문 검토**를 다시 열고 반영을 시도합니다. 창이 남으면 위쪽 **반영 상태 확인 · 진단판 3**을 펼치고 **진단 내용 복사**를 누릅니다. 수정판 4에서는 **반영 상태 확인 · 연결 오류 수정판 4**로 표시됩니다. 어느 항목도 없다면 현재 화면에 진단 기능이 포함된 코드가 로드되지 않은 것입니다.
4. 복사한 진단 내용으로 버튼 클릭 횟수, 반영 단계, 잠금 상태, 저장 중 여부, AI 응답 상태를 확인할 수 있습니다. 클립보드 복사가 허용되지 않으면 선택된 진단 내용을 `Ctrl+C`로 복사합니다.

진단에는 프로젝트 내용·질문·답변·노드 및 요청 ID·연결 코드를 포함하지 않습니다. 반영 실패 시 오류 위치로 이동하고, 기존 검토 응답은 유지합니다. 전체 자동 테스트 **186개**와 구문 검사를 통과했고, Chromium에서 저장 완료 대기 중 진단 복사, 비공개 내용 제외, 저장 재개 및 새로고침 후 유지까지 확인했습니다.

## v0.8.0 질문·제약 검토 반영 수정

- **두 번째 수정판 (`decision-apply-fix2`)**: 모든 AI가 **응답 도착**이어도 후속 CLI 연결 점검을 기다리느라 반영 버튼이 잠기는 문제를 수정했습니다. 완료된 검토 결과는 즉시 반영할 수 있고 연결 점검은 별도로 진행됩니다. 연결 점검의 지연·실패가 결과 저장을 막지 않습니다.
- **현재 노드의 질문·제약 검토 → 이 응답 반영**을 체크하거나 해제하면 **선택한 결과 반영** 버튼이 즉시 갱신됩니다. 선택을 해제한 응답을 다시 열어 체크해도 정상적으로 반영할 수 있습니다.
- 저장 후 새 질문·제약이 있는 상태 탭과 항목을 표시합니다. 이전 노드 필터가 결과를 가리는 경우 전체 노드로 전환하며, 추가·갱신 건수 또는 변경 항목이 없다는 안내를 표시합니다.
- 저장 실패 시 응답과 선택을 유지하며, 재시도할 수 있습니다. 기존 답변·확정 상태는 유지합니다.

검증: 회귀 테스트 10개를 포함한 전체 자동 테스트 **184개**와 구문 검사를 통과했습니다. Chromium에서 테스트용 CLI 요청, 선택 해제·재선택에 따른 버튼 상태, 세션에 남은 미선택 응답 반영, 제약 표시, 새로고침 후 저장 내용을 확인했습니다. 세 AI 모두 응답한 뒤 연결 점검 응답 3개를 지연시킨 상태에서도 반영 클릭 → 창 닫힘 → 질문과 AI 의견 3개 저장을 확인했으며, 연결 점검을 실패시킨 뒤 새로고침해도 저장 내용이 유지됐습니다. Windows의 실제 CLI 계정 호출은 검증하지 않았습니다.

교체 방법: 실행 중인 기존 서버를 Ctrl+C로 종료하고 수정 ZIP을 새 폴더에 압축 해제한 뒤 `start-windows.cmd`를 실행하세요. 기존과 같은 브라우저·주소(예: `http://127.0.0.1:4173`)로 접속하고 새로고침하면 저장된 프로젝트를 계속 사용할 수 있습니다. 미반영 응답은 같은 브라우저 탭의 세션에 있으므로 그 탭에서 새로고침하세요.

## AI로 노드 정리 · 구현 순서

기획 보드에서 노드를 선택하고 **AI로 노드 정리**를 요청하면 상하위 구조와 구현 의존성을 함께 제안합니다. 적용 전 미리보기에서 내용을 확인합니다.

- **통합 기획도**는 기능의 포함 관계입니다. 실제 작업이 없는 상위 노드는 **기능 묶음**으로 지정할 수 있으며 개발 대상에서 제외됩니다. 하위 노드가 있다는 이유만으로 자동으로 묶음이 되지는 않습니다.
- **구현 순서** 보기에서 선행 작업, 의존 단계, 우선순위, 함수 구현 단계를 확인합니다. 실행은 `dependsOn`을 우선하며, 준비된 작업 사이에서 `order`가 작은 것을 먼저 선택합니다. 상위·하위 위치나 카드 이동은 실행 의존성을 바꾸지 않습니다. 현재 작업은 순차 실행합니다.
- 노드의 **내용 수정 → 구현 순서 · 선행 작업**에서 직접 편집할 수 있습니다. 함수 단계는 스키마·검증 → 계산 → 상태 → 외부 연동 → UI를 참고하되 필요한 단계만 사용합니다. 함수 작성 시간순을 강제하지 않으며 계약·mock은 실제 기능 검증과 구분합니다.
- AI 정리에서 선택하지 않은 노드와의 의존성을 유지하고 병합된 ID를 다시 연결합니다. 선행 작업 삭제 시 후속 작업에 재확인 사항을 남깁니다. 재확인하지 않은 작업과 그 후속 작업은 대기하고 독립 작업은 계속합니다. 순환·자기 참조·존재하지 않는 선행 작업은 저장할 수 없습니다.
- 기존 기획의 빈 선행 목록은 **미검토**로 표시합니다. 기존 데이터는 계속 사용할 수 있으나 실제 의존성이 없는지는 AI 정리 또는 직접 편집으로 확인하세요. 미검토 경고와 삭제·누락에 따른 실행 보류는 별도입니다.
- 적용한 순서와 함수 단계는 새 **기획 확정 → 업무 분담안 저장 → 개발·검토**까지 전달됩니다. 이전 확정본과 진행 이력은 바꾸지 않으며, 새 확정본을 선택해야 변경 내용으로 실행합니다. 업무 분담 화면에서 선행 작업을 조정한 경우 해당 분담안이 실행 기준입니다.
- 순서 검사는 Agent Desk 실행기에서 수행합니다. 공급자별 Hook 설치에 의존하지 않으며 함수 이름·파일 존재·구문 검사만으로 작업 완료를 판정하지 않습니다. 완료 여부는 설정한 검사와 독립 검토 결과에 따릅니다.

## v0.8.0 개발·검토

프로젝트 상단의 **개발·검토**에서 사용합니다. 기획 확정 화면의 **협업 방식 선택 →**도 같은 페이지를 엽니다.

1. **협업 방식**: 통합안(기본) → 운영 절차 중심 → 검증 중심 → 쟁점 분석 중심 → 기존 업무 분담안 중 하나를 선택합니다. 옆의 흐름도와 장점·단점·한계가 함께 바뀝니다. 이 순서대로 자동 실행하는 기능은 아닙니다.
2. **담당 AI**: 전체 총괄, 주 Builder, 주 Auditor, 주 Challenger를 Codex·Claude·AGY 중에서 각각 정합니다. 프로젝트 기본 배정을 사용하거나 방안마다 별도 배정합니다. 총괄은 역할을 겸임할 수 있으며 Builder와 Auditor는 달라야 합니다. 기존 분담안 방식에서는 업무별 개발자 배정을 유지하고 독립 검토자를 표시합니다.
3. **실행 조건**: 확정 기획과 저장한 업무 분담안, 현재 PC의 실제 작업 폴더, Git, 사용할 CLI의 설치·로그인이 필요합니다. 빈 작업 폴더에서 새 프로그램을 만들 수도 있습니다. 미답변 질문은 확정본에 보존하며 관련 작업의 판단 근거로 전달합니다.
4. **검사·실행 설정**: 검사 명령은 실행 파일과 JSON 인수를 나누어 입력합니다. 예: `npm` + `["test"]`. 정적 웹은 시작 파일을 지정합니다. 서버 프로그램은 실행 준비 명령(예: `npm` + `["ci"]`), 실행 명령(예: `npm` + `["start"]`), 확인 주소 `http://127.0.0.1:{port}/`를 지정합니다. 프로그램은 `PORT` 환경 변수로 배정된 포트를 사용해야 합니다. 의존성 설치나 검사 명령을 임의로 추정해 실행하지 않습니다.
5. **작업 진행**: 실행 범위를 확인한 뒤 시작합니다. 기본 AI 대기는 무제한이며 요청을 취소할 수 있습니다. 화면을 이동하거나 새로고침해도 현재 PC 실행기가 작업을 계속합니다. 실행기를 종료했다면 자동 재시작하지 않고 중단된 이력을 표시합니다.
6. **검토 결과·기록**: 코드 버전, 실제 검사 결과, 독립 검토 판정, 남은 한계를 확인합니다. 시작 확인을 통과한 결과물은 실행하거나 Windows용 ZIP으로 내려받을 수 있습니다. **시작 주소 응답, 기능 검증, 독립 검토 통과는 서로 다른 상태**입니다. 새 후보가 실패해도 이전 실행 가능 버전은 남습니다.

테스트를 실행하려면 아래 개발 및 검증 절차의 `npm ci`로 jsdom 등 개발 의존성을 먼저 설치하세요. 존재하지 않는 decimal.js 버전을 가리키던 잠금 파일도 검증된 패키지 정보로 수정했습니다. 앱 자체를 실행할 때는 패키지 설치가 필요 없습니다.

검증: 노드 정리·구현 순서 업그레이드를 포함한 전체 자동 테스트 **174개**와 구문 검사를 통과했습니다. 테스트용 CLI 프로세스로 실제 파일 생성·Git SHA 고정·검사·역할 교체·부분 재실행·취소를 확인했고, Chromium에서 역할 설정과 프로그램 실행·ZIP 다운로드·새로고침 후 결과 보존을 확인했습니다. 노드 구현 순서, 함수 단계 편집·재로드, 모바일 화면도 확인했습니다. 유료 공급자 계정과 Windows 실기기 실행은 수행하지 않았습니다.

### 다른 방식으로 필요한 부분만 다시 실행

방식을 바꾸고 **실행 범위 확인**을 누르면 재구현·추가 검증·결과 유지·조건 대기·쟁점 분석을 작업별로 표시합니다. 실패·미개발·수정 가능한 한계는 다시 구현하고, 완료된 작업은 보존하되 변경 영향을 받으면 재검증합니다. 사용자가 수용한 한계는 자동으로 다시 열지 않습니다. 환경·자료·기획 문제를 코드 수정으로 간주하지 않습니다.

수정 2회, 검토 3회, AI 조합 교체 1회는 **변경 가능한 기본값**입니다. 통합안에서 자동 조합 교체를 켜면 한도에 도달한 미해결 작업에 다른 조합을 제한적으로 사용합니다. 조합별 허용 횟수와 작업 전체 누적 기록을 구분하며, 교체나 방식 변경으로 과거 기록을 초기화하지 않습니다. 이전 코드 작성자가 자신의 기여를 최종 검토하는 조합은 허용하지 않습니다.

### 저장과 실행 범위

- 역할·방식·한도·실행 설정은 프로젝트 JSON 백업에 포함됩니다. 실제 실행 이력과 결과물은 PC의 사용자 홈 아래 `.agent-desk/development/`에 저장되며 브라우저 백업과 별개입니다. 다른 PC로 옮길 때는 실행기 종료 후 이 폴더도 별도로 보관해야 합니다. 경로와 설치 환경은 PC마다 다시 확인합니다.
- 원본 폴더는 수정하지 않습니다. 실행기가 별도 작업본에 AI의 구조화된 파일 변경을 적용하고, 고정 코드 버전에서 설정한 검사를 실제 실행합니다. `.git`, `node_modules`, 비밀 설정 파일은 결과물 복사·다운로드에서 제외합니다. 필요한 의존성은 명시한 준비 명령으로 설치합니다.
- AI는 이 경로에서 자유롭게 셸을 조작하지 않습니다. 공식 CLI의 구조화 응답으로 파일 내용을 제안하고, 실행기가 경로 검증 후 적용합니다. Auditor는 전달된 코드와 실행 근거를 독립적으로 검토합니다. 보고서의 검사 근거는 실행기가 실제 수행한 명령에 한정하며, AI의 서술을 실행 사실로 간주하지 않습니다.
- 현재 작업본은 최대 4,000개 파일·총 64MB, 한 번의 AI 코드 문맥은 약 120KB로 제한합니다. 큰 저장소는 독립 실행 가능한 작은 작업 폴더로 나누어야 합니다. 범위를 넘으면 일부 코드를 몰래 누락하지 않고 중단 이유를 표시합니다.
- GitHub push·PR 승인·main 병합은 자동으로 수행하지 않습니다. 실행 가능한 결과에 남은 문제를 수용해도 Auditor의 불통과·보류 판정은 통과로 바뀌지 않습니다.

## v0.7.1 대기 시간·취소·기획 확정 수정

- AI 응답의 기본 최대 대기 시간은 **무제한**입니다. 5분·10분·20분을 직접 고를 수도 있습니다. 이전에 저장한 제한 시간은 유지되므로 무제한으로 바꾸려면 **AI 연결 → 최대 대기 시간 → 무제한 → 모델 설정 저장**을 사용하세요. 모델 목록·설치 확인에는 별도 제한 시간이 있습니다. 외부 CLI와 서비스 자체의 제한·오류는 별개이며, AGY에는 무제한 모드에서 앱이 강제로 지정하던 `--print-timeout`을 보내지 않습니다.
- 응답 테스트·기획 요청·질문 검토·업무 분담·노드 정리에서 요청 취소를 사용할 수 있습니다. 서버의 작업 번호가 도착하기 전에도 취소를 기록해 늦게 도착한 요청이 실행되지 않도록 합니다. 연결이 끊겨 취소를 확인할 수 없다면 상태 확인 안내를 표시합니다.
- 중요한 미답변 질문도 남긴 채 기획을 확정할 수 있습니다. 기획 확정 메모와 확인 체크는 답변·분담안 편집과 별도로 보관하므로 탭 이동을 막지 않습니다. 메모는 브라우저 탭의 세션에 임시 저장되고, 기획이 바뀌면 확인 체크를 다시 선택합니다. 저장 실패 시 메모를 유지합니다.
- 이미 확정된 기획에는 완료 상태를 표시합니다. 작업 노드·미해결 결정 충돌·완료 기준 때문에 확정할 수 없는 경우 이유를 표시하고, 이전 단계로 돌아갈 수 있습니다.
- **Windows 다운로드**는 현재 실행 중인 폴더의 소스로 ZIP을 만듭니다. 다른 사이트의 예전 ZIP으로 이동하지 않습니다. 실행창에 버전과 폴더를 표시하며, 기존 서버가 포트를 사용 중이면 그 서버를 먼저 종료하도록 안내합니다.

검증: 구문 검사와 자동 테스트 88개를 통과했습니다. Chromium에서 기본 무제한 요청의 취소, 미답변 16개를 남긴 기획 확정, 메모 보존과 탭 이동, 새로고침, 현재 버전 ZIP 다운로드를 확인했습니다. 실제 CLI 계정 요청은 실행하지 않았으며 AGY 자체 기본 제한은 확인하지 못했습니다.

## v0.7.0 질문·결정부터 기획 확정까지

1. **기획 보드 → 질문·결정**에서 현재 노드의 질문을 직접 추가하거나 **AI로 질문 검토**를 요청합니다. AI 연결에서 저장한 모델·강도·대기 시간을 사용합니다. 응답을 미리 보고 선택한 결과만 반영합니다. 일부 AI가 실패해도 나머지 응답을 반영할 수 있습니다.
2. **답변 필요 / 확인 필요 / 결정 완료** 탭에서 항목 하나의 질문과 답변·근거를 한 패널로 관리합니다. 사용자 결정·추가 확인·제약·결정 충돌을 구분합니다. 중요한 질문도 미답변 상태로 기획을 확정할 수 있습니다. 미답변·미확정 항목은 그대로 남으며, 명시적으로 보류할 때에는 이유가 필요합니다. 확정한 답변은 다시 검토하거나 이력을 볼 수 있습니다.
3. 같은 노드에 대한 같은 질문은 하나로 합치고 각 AI 의견·선택지·근거를 보존합니다. 의미가 비슷할 뿐 문장이 다른 질문은 자동으로 합치지 않습니다. AI 의견은 사용자 답변으로 확정되지 않습니다.
4. 노드 정리를 **적용할 때** 질문도 함께 정리합니다. 삭제한 노드에만 속한 항목은 제거하고, 공유 질문은 남은 노드에 유지하며, 통합한 노드로 질문을 연결합니다. 기존 답변이 서로 다르면 보존합니다. 답변한 노드의 내용·상위 관계가 바뀌면 답변을 보존하고 **확인 필요**로 전환합니다. 위치 이동만으로는 답변을 무효화하지 않습니다. 되돌리기는 노드와 질문을 함께 복원합니다.
5. **AI 결정 충돌 검토**는 확정 답변 사이의 모순을 검토합니다. 결과에는 관련 결정과 이유가 연결되며 AI가 답변을 덮어쓰지 않습니다. 실제 사실 확인이나 웹 조사를 수행하는 기능은 아니므로 AI 근거를 사용자가 확인해야 합니다.
6. **기획 확정 · 업무 분담**에서 중요한 미결정·미해결 충돌·완료 기준을 점검합니다. 미답변·미검토·보류를 확인하고 확정하면 목표·공통 지침·노드·질문·답변의 스냅샷을 버전으로 저장합니다. 기획 확정은 개별 질문을 답변 완료로 바꾸지 않으며, 미답변 항목은 업무 분담서에도 포함됩니다. 작업 노드가 없거나 완료 기준이 비어 있거나 미해결 결정 충돌이 있으면 해당 사항을 먼저 정리합니다. 이후 편집은 이전 확정 내용을 바꾸지 않습니다.
7. 확정 버전에서 **AI로 업무 분담안 만들기**를 요청하거나 직접 초안을 편집합니다. 모든 작업 노드의 담당 AI·선행 작업·업무 지시·기대 결과·완료 기준을 확인하고 저장합니다. 순환 의존은 저장할 수 없습니다. 저장한 분담서를 Markdown으로 내려받을 수 있습니다. 이 단계에서는 코드를 구현하거나 작업을 실행하지 않습니다.

질문은 최대 300개, AI 질문 응답 한 건은 최대 60개, 확정 버전은 최근 10개, 답변 이력은 항목당 최근 20개입니다. 미검토 노드는 질문이 없다는 뜻이 아닙니다. 확정 버전·분담안·질문 이력은 기존 프로젝트 JSON 백업에 포함됩니다. 미반영 AI 응답은 탭 세션에만 보관되므로 다른 PC로 이동하기 전에 반영하세요.

검증: 구문 검사와 자동 테스트 69개를 통과했습니다. 실제 프로세스와 테스트용 CLI, DOM 통합 테스트에 더해 Chromium에서 중요 질문 17개와 일반 질문 4개를 미답변으로 남긴 채 기획 확정·업무 분담서 저장 및 다운로드·새로고침 후 보존을 확인했습니다. Windows 실계정의 모델별 응답은 해당 PC에서 확인해야 합니다.

## 회사와 집에서 이어서 사용하기

**프로그램 코드**와 **브라우저에 저장된 프로젝트 기획**을 구분합니다.

- 프로그램: 이 저장소 또는 Windows ZIP의 `public/`, `scripts/` 등입니다. Git으로 버전을 관리할 수 있습니다.
- 프로젝트 기획: KAF 설명·노드·대화·질문·답변·확정 버전·분담안·첨부입니다. 현재 브라우저의 IndexedDB에 있으며 자동으로 Git에 저장되지 않습니다.

### 지금 가능한 이동 방법

1. 집 화면에서 **프로젝트·기획 백업**(프로젝트 하나) 또는 **전체 프로젝트 백업**을 눌러 JSON 파일을 저장합니다.
2. 회사 PC에서 최신 Windows ZIP을 풀고 `start-windows.cmd`를 실행합니다. Node.js 20 이상이 필요합니다.
3. 프로젝트 목록의 **가져오기**에서 JSON을 선택합니다. 기존 프로젝트를 덮어쓰지 않고 이름에 `가져옴`이 붙은 복사본을 추가합니다. 최신 복사본에서 계속 작업하세요.
4. **프로젝트 정보 → 현재 PC 폴더**를 회사 폴더로 다시 선택합니다. Git 주소는 공통으로 사용해도 폴더 경로와 접근 권한은 PC마다 다릅니다.
5. 회사 PC의 Codex·Claude·AGY CLI 로그인과 **AI 연결**을 확인합니다. 모델 선택, 연결 코드, 임시 응답과 토큰 집계는 프로젝트 백업으로 옮기지 않습니다.
6. 집으로 돌아오기 전에 회사에서 최신 JSON을 백업하고 집에서 가져옵니다. 두 PC에서 따로 수정한 기획의 자동 병합은 지원하지 않습니다.

하단 **다른 PC에서 이어하기**에서도 위 안내와 백업 버튼을 제공합니다. 같은 웹 주소를 두 PC에서 열어도 브라우저 저장소는 별개입니다. 로컬 주소와 웹 대시보드 사이를 옮길 때도 백업/가져오기가 필요합니다.

### Git 용어와 프로그램 개발 이어하기

| 용어 | 의미 |
| --- | --- |
| Git | 코드 변경 이력을 관리하는 도구 |
| GitHub | Git 저장소를 온라인으로 보관하는 서비스 |
| commit | 현재 PC에서 변경 내용을 한 버전으로 기록 |
| push | 커밋을 GitHub에 올리기 |
| clone | 다른 PC에서 저장소를 처음 내려받아 Git 연결을 만들기 |
| pull | 이미 받은 저장소에 최신 변경분 가져오기 |
| 배포 | 사용자가 웹 주소 등에서 실행할 수 있도록 공개/업데이트하기 |

GitHub에 게시된 코드를 처음 받는 예입니다. 현재 로컬 변경이 아직 push되지 않았다면 아래 clone에는 새 기능이 포함되지 않습니다. 이 경우 현재 실행판의 Windows 다운로드 ZIP을 사용하세요:

```powershell
git clone https://github.com/MyungRag/Codex_Claude_AGY.git
cd Codex_Claude_AGY
.\start-windows.cmd
```

이후 같은 폴더에서 최신 코드를 받을 때는 `git pull`을 사용합니다. 다른 PC로 가기 전 자신의 수정 내용을 commit하고 push합니다. ZIP 다운로드는 Git 연결이 없는 파일 복사이므로 ZIP 폴더에서 바로 `git pull`할 수 없습니다. 프로그램 코드가 담긴 브랜치인지 먼저 확인하세요. 비공개 저장소는 같은 GitHub 계정으로 로그인해야 합니다. KAF 기획 JSON은 위 백업 절차로 별도 이동합니다.

## 현재 PC 폴더와 Git 주소

프로젝트와 첨부 자료는 **현재 사이트 주소의 현재 브라우저**에 저장됩니다. 같은 PC라도 주소, 포트 또는 브라우저가 다르면 별도의 저장소입니다. 브라우저 데이터를 삭제하면 자료도 삭제됩니다. 중요한 설정은 내보내기로 백업하세요.

작업 폴더는 지금 사용하는 PC의 경로를 등록합니다. Git 주소는 프로젝트 저장소를 가리키는 별도 항목으로, 등록만으로 복제·동기화·푸시를 실행하지 않습니다. 다른 PC에서 사용할 때에는 해당 PC의 폴더를 선택하세요. 프로젝트 정보는 자동 동기화되지 않으므로 설정을 옮기려면 내보내기/가져오기를 사용하세요. 가져오기는 기존 프로젝트를 덮어쓰지 않고 사본을 추가합니다. 가져온 뒤 현재 PC의 경로를 확인하세요. 전체 백업이 30MB를 넘으면 프로젝트별로 내보내세요.

v0.3.0은 기존 회사/집 프로필 중 마지막으로 선택했던 프로필의 경로를 현재 PC 경로로 옮깁니다. 해당 경로가 비어 있으면 다른 기존 경로를 사용합니다. 두 기존 경로와 폴더 이름도 백업 데이터에 보존하며, 이후 현재 PC 경로를 비워도 옛 경로를 다시 채우지 않습니다.

**웹에서는 `폴더 선택` 버튼으로 폴더를 고를 수 있습니다.** HTTPS 또는 localhost의 지원 브라우저(Edge/Chrome)에서 폴더 이름과 디렉터리 핸들을 저장합니다. 웹 API는 전체 Windows 경로를 제공하지 않으므로 임의의 경로를 만들지 않습니다. 전체 경로는 직접 입력할 수도 있습니다. 선택한 폴더의 파일을 읽거나 업로드하지 않습니다. 내보내기에는 경로·폴더 이름·Git 주소가 포함되며, 디렉터리 접근 권한은 다른 PC로 이전되지 않습니다.

**Windows 로컬 실행판은 시스템 폴더 선택창으로 전체 경로를 입력합니다.** `start-windows.cmd`로 실행한 최신 버전에서 지원합니다. 로컬 폴더 선택 API는 같은 PC의 Agent Desk 화면에서만 사용할 수 있습니다.

프로젝트 삭제는 이 브라우저에 저장된 프로젝트 정보, 첨부 사본, 디렉터리 핸들을 제거합니다. 실제 작업 폴더와 원본 파일은 삭제하지 않습니다. 보관함은 복원이 가능하지만 삭제는 복원할 수 없습니다.

v0.5.0부터 현재 PC의 공식 CLI를 통해 실제 기획 응답을 요청할 수 있습니다. 코드 구현·파일 편집을 실행하는 작업 모드는 후속 단계입니다.

## v0.4.0 기획 보드

프로젝트를 연 뒤 **기획 보드**를 선택합니다. 프로젝트 설명으로 기본 구조를 만들거나 빈 목표에서 시작할 수 있습니다. 기본 초안은 로컬 규칙에 따른 편집 틀이며 실제 AI 생성 결과가 아닙니다. **KAF 시연으로 기능 둘러보기**는 세 에이전트의 제안 비교와 통합을 시험하기 위한 고정 예시입니다. 화면과 원본에 시연 여부를 표시합니다.

- 연결선의 `+`: 두 노드 사이에 삽입하거나 같은 단계에 가지 추가
- 노드 아래 `+`: 하위 노드 추가
- 노드의 수정 버튼: 이름·설명·업무 지시·완료 기준·기획 상태 수정
- 노드의 `−`: 해당 노드만 삭제하고 연결 유지, 또는 하위 노드까지 삭제
- 드래그로 위치 이동, 빈 캔버스로 이동, 확대·축소, 화면 맞춤, 자동 정렬, 가지 접기
- 상위 노드 변경: 노드 관계 편집 (자기 자신·하위 노드로의 순환 금지)
- 여러 노드 선택 → 합치기: 합친 내용을 검토하고 원본 제안·대화·연결 관계 보존
- 동일한 내용과 상위 노드의 제안만 자동 통합, 비슷한 이름은 검토 후보로 표시
- 에이전트별 비교에서 원본 확인, 제외된 제안 다시 추가
- 노드별·전체 대화 저장, 대화를 노드로 추가하거나 업무 지시에 반영
- 변경 이력과 되돌리기·다시 실행 (새로고침 후에도 유지)

### 세 도구와 함께 기획하기

1. 보드의 **검토 요청문 복사**를 눌러 Codex, Claude, Antigravity에 각각 붙여넣습니다. 프로젝트 설명·공통 지침·현재 기획·이전 피드백·제외된 제안이 포함됩니다.
2. 각 도구에서 받은 결과를 **제안 가져오기**에 붙여넣고 해당 에이전트를 선택합니다.
3. 노드 제안은 요청문에 안내된 JSON 형식을 사용합니다. 일반적인 검토 의견은 **검토 의견 · 일반 텍스트**로 가져옵니다.
4. 같은 제안은 하나로 통합됩니다. 특정 에이전트만 제안한 노드와 서로 다른 내용은 별도로 검토합니다.

이 수동 가져오기 방식은 계속 사용할 수 있습니다. v0.5.0의 AI 기획 요청을 쓰면 PC 실행기가 호출과 응답 수집을 담당합니다. 아래 연결 안내를 참고하세요.

기획은 프로젝트와 함께 현재 주소의 이 브라우저에 저장됩니다. 기존 프로젝트 내보내기/가져오기에 노드·제안 원본·대화·이력도 포함됩니다. 프로젝트별 최대 노드 100개, 제안 300개, 대화 200개이며 최근 12단계까지 되돌릴 수 있습니다. 큰 기획에서는 저장 크기에 맞춰 오래된 되돌리기 기록부터 줄입니다. 노드 이름이나 배치는 자유롭게 변경할 수 있으나 순환 관계나 연결되지 않은 노드는 허용하지 않습니다.

## v0.6.2 Claude 모델 표시·진행 상황·대기 시간

Sonnet 5.5는 Max를 지원합니다. Max를 선택한 요청이 5분 제한에 걸린 것만으로 모델 미지원이나 로그인 실패를 판단할 수는 없습니다. 이 수정판은 오류를 구분하고 지연을 확인할 수 있도록 보완합니다.

- Claude 목록의 모델 이름과 CLI 선택값, CLI가 제공한 `resolvedModel`을 함께 표시합니다. `sonnet` 같은 별칭과 실제 모델 버전을 구분합니다. CLI가 제공한 원래 선택값은 그대로 전송하며 `[1m]` 같은 접미사를 제거하지 않습니다.
- Claude는 `--output-format stream-json --verbose --include-partial-messages`로 실행합니다. 초기화·응답 이벤트·최종 응답 수신 상태와 CLI 보고 모델을 완료 전에도 표시합니다. 내부 추론 원문이나 프로젝트 내용은 진행 상태 및 진단 결과에 넣지 않습니다.
- AI 연결과 노드 정리에서 **최대 대기 시간 무제한·5분·10분·20분**을 고를 수 있습니다. v0.7.1부터 기본은 무제한이며, 명시적으로 선택한 제한 시간을 자동으로 늘리거나 재시도하지 않습니다. AI 연결에서 저장한 시간은 응답 테스트·기획 요청에, 노드 정리에서 고른 시간은 해당 정리에 적용됩니다.
- 시간 초과는 `AGENT_TIMEOUT`으로 구분합니다. 경과 시간과 마지막 이벤트 시각이 표시되며, 성공한 연결이나 모델 지원 여부를 지우지 않습니다. 토큰은 CLI가 보고한 값만 집계합니다. 스트림 조각을 최종 사용량에 더하지 않습니다.
- 모델·강도·대기 시간 선택 후 **모델 설정 저장 → 응답 테스트**를 누르세요. Max로 오래 걸리는 요청은 먼저 최대 대기 시간을 확인하고 필요하면 직접 늘려서 새로 요청하세요. 진행 중 요청은 취소할 수 있습니다.
- 설치: 기존 실행기 명령창을 닫고 새 ZIP의 **start-windows.cmd**를 실행합니다. AI 연결에서 **PC 실행기 v0.6.2**를 확인합니다. 웹 새로고침만으로 실행기가 업데이트되지는 않습니다.

선택값·스트림·시간 초과·취소·진행 표시·기존 노드 정리는 테스트용 CLI 프로세스와 DOM 통합 검사로 검증합니다. 사용자 Windows의 실계정에서 발생한 지연 원인은 아직 재현하지 못했습니다.

## v0.6.1 모델별 추론 강도 호환성 수정

이전 버전은 모델별 지원 여부와 관계없이 Max까지 표시했습니다. 이제 CLI가 제공한 지원 범위만 선택할 수 있습니다.

1. 기존 실행기 명령창을 닫고 **새 ZIP의 start-windows.cmd**를 실행합니다. AI 연결에서 **PC 실행기 v0.6.1**을 확인합니다.
2. AGY·Claude 카드의 **기본값으로 재설정 → 응답 테스트**를 누릅니다. 성공하면 모델 목록을 자동 조회합니다.
3. 원하는 모델을 고르고 표시된 추론 강도를 선택해 **모델 설정 저장 → 응답 테스트**로 확인합니다.

- 저장돼 있던 미지원 Max는 경고와 함께 비활성 선택지로 표시됩니다. 직접 기본값으로 재설정하거나 지원되는 강도를 고르기 전에는 전송되지 않습니다.
- 모델을 바꾸면 지원 강도가 즉시 바뀝니다. 기존 강도를 쓸 수 없는 모델이면 화면에 알리고 기본값으로 돌립니다. 모델의 강도 정보가 없거나 조정 불가능하면 기본값만 표시합니다.
- 기본 모델이 어떤 모델인지 확인되지 않으면 강도를 추측하지 않습니다. 목록에서 모델을 직접 고르세요. 목록 조회 실패는 정상적인 기본값 요청을 막지 않습니다.
- 연결의 최근 성공 기록과 현재 선택한 모델·강도의 응답 확인을 구분합니다. 모델·강도 오류가 다른 설정의 연결 성공 기록을 지우지 않습니다.
- CLI가 거절한 조합은 현재 실행기 세션에서 차단합니다. 조직 정책·계정 권한을 바꾼 뒤 같은 조합을 재확인하려면 실행기를 재시작하고 목록을 다시 불러오세요. 로그인 오류와 사용량 한도는 별도로 안내합니다.
- AI 기획 요청과 AI 노드 정리에도 같은 검사를 적용합니다. 호환되지 않는 요청은 모델 실행 전에 막으며, 다른 모델·강도로 유료 요청을 자동 재시도하지 않습니다.
- 목록 조회는 모델 응답을 생성하지 않습니다. 응답 테스트·기획·정리 요청에는 계정 사용량이 적용됩니다.

## v0.6.0 모델·토큰·AI 노드 정리

### 모델과 추론 강도 선택

**AI 연결 → 에이전트 카드 → AI 모델 / 추론 강도 → 모델 설정 저장**에서 선택합니다. 예: Codex **GPT-6 Astra + Extra High**. 이 설정은 현재 주소의 브라우저에 저장되며 응답 테스트와 다음 기획 요청에 적용됩니다. 응답 카드에는 요청한 모델·추론 강도와, CLI가 보고한 경우 실제 모델도 표시합니다.

- Codex: **모델 목록 불러오기**는 공식 app-server의 `model/list`로 이 PC에서 조회한 모델과 지원 추론 강도를 표시합니다. 모델 실행 요청 없이 목록만 읽습니다. 기본 추천 목록에는 GPT-6 Astra와 GPT-6.1 Sol이 있습니다.
- Claude: 공식 Agent SDK의 initialize 제어 응답으로 현재 CLI의 모델 목록과 `supportedEffortLevels`를 읽습니다. 사용자 프롬프트는 보내지 않으며, 고정된 별칭만으로 Max 지원을 추측하지 않습니다.
- AGY: `agy models --output-format json`을 읽으며 JSON이 지원되지 않으면 `agy models`의 탭 구분 목록을 읽습니다. CLI가 명시한 강도 또는 실제 공개된 모델 변형만 사용합니다. 모델 ID 직접 입력 시에는 지원 정보가 확인될 때까지 기본 강도로 사용합니다.
- Extra High는 `xhigh`로 전달합니다. Codex는 `--model`과 `-c model_reasoning_effort=...`, Claude·AGY는 `--model`과 `--effort`를 사용합니다. 계정·모델·CLI 버전에 따른 실제 지원은 응답 테스트로 확인합니다. 지원되지 않는 설정을 다른 모델로 자동 교체하지 않습니다.
- 모델 호환성 검사에는 PC 실행기 v0.6.1 이상이 필요합니다. 구 실행기가 새 모델 설정을 무시한 채 요청하지 않도록 버전을 확인합니다.

### AI별 토큰 사용량

AI 연결의 **에이전트별 사용량**, 기획 보드 상단, 각 응답 카드에서 확인합니다. 집계 범위는 **현재 PC 실행기 시작 이후 이 대시보드가 보낸 요청**이며 응답 테스트·기획·노드 정리를 포함합니다. 실행기를 재시작하면 누적 집계는 새로 시작합니다. 완료된 응답을 확인할 때 갱신되며 계정 전체 사용량·잔여 한도를 조회하지 않습니다.

입력·출력·합계와 제공되는 경우 캐시 읽기·캐시 생성·추론 토큰을 표시합니다. CLI가 보고하지 않은 수치는 **미제공**으로 표시합니다. 실패한 응답도 CLI가 보고한 토큰이 있으면 집계합니다. Claude의 입력 집계는 일반 입력과 캐시 읽기·생성을 합한 값입니다. 캐시·추론 상세 수치를 합계에 다시 더하지 않으며, AGY는 제공된 `total_tokens`를 우선 사용합니다. 표시값을 요금으로 환산하지 않습니다.

### 전체 또는 선택한 노드 정리

1. 기획 보드의 **전체 선택**을 누르거나 여러 작업 노드를 선택합니다. 전체 목표 노드는 유지합니다.
2. **AI로 노드 정리**를 누릅니다. 선택이 없으면 모든 작업 노드를 대상으로 합니다.
3. 정리 담당 에이전트·모델·추론 강도와 정리 방향을 선택하고 **정리안 만들기**를 누릅니다. 이번 요청의 모델 설정은 AI 연결의 기본 설정을 바꾸지 않습니다.
4. 정리 후 계층, 병합할 원본, 바뀔 설명·업무 지시·완료 기준, 제외할 노드와 이유를 검토합니다.
5. **정리안 적용**을 누르면 그래프가 바뀝니다. 변경 이력과 **되돌리기 / 다시 실행**으로 복원할 수 있습니다.

모든 선택 노드는 정리 결과의 원본 목록에 한 번씩 들어가거나 명시적인 제외 이유가 있어야 합니다. 누락·중복·순환·연결 단절이 있으면 적용하지 않습니다. 선택하지 않은 노드와 경계 연결을 유지하고, 합친 노드로 원본 제안과 대화를 연결합니다. 제외한 제안과 대화도 기록에 남습니다. 요청 중 다른 탭에서 기획을 수정했다면 이전 결과가 최신 기획을 덮어쓰지 않습니다.

정리안의 미반영 결과는 현재 브라우저 탭 세션에 임시 저장됩니다. 새로고침 후 같은 프로젝트의 **AI로 노드 정리**를 열면 이어서 확인할 수 있습니다. 전체 노드 100개, 제안 300개, 대화 200개의 기존 저장 한도는 유지됩니다. AI 정리는 한 번의 요청이며 변경안 승인 후 적용합니다.

실제 Codex CLI의 모델 목록에서 GPT-6 Astra와 Extra High를 확인했습니다. 나머지 실행 옵션·사용량 파싱·정리안 적용은 테스트용 CLI 프로세스와 DOM 통합 테스트로 검증했습니다. 사용자 Windows 계정에서 모델별 실행 확인은 응답 테스트로 진행합니다. 현재 브라우저 제어 도구는 `the gaas-browser node_repl sandbox cannot be disabled` 오류로 실제 화면 검증에 사용할 수 없었습니다.

## v0.5.0 실제 AI 연결

### Windows에서 준비

데스크톱 앱의 설치·로그인과 CLI의 설치·로그인은 다를 수 있습니다. 아래 공식 안내에 따라 **CLI**를 준비하고 PowerShell에서 확인합니다. 각 도구가 제공하는 최신 버전을 사용하세요. CLI 로그인은 해당 서비스의 공식 화면에서 진행합니다.

| 도구 | 공식 설치 안내 | 버전 확인 | 로그인 |
| --- | --- | --- | --- |
| Codex | https://developers.openai.com/codex/cli/ | `codex --version` | `codex login` |
| Claude Code | https://code.claude.com/docs/en/setup | `claude --version` | `claude auth login` |
| Antigravity CLI | https://antigravity.google/docs/install?tab=cli | `agy --version` | `agy`를 처음 실행하고 로그인 |

Codex는 공식 npm 패키지 `npm install -g @openai/codex`로도 설치할 수 있습니다. Antigravity 데스크톱 실행 명령과 `agy` CLI는 구분됩니다. 설치·로그인 후에는 실행기를 다시 시작해야 변경된 PATH가 반영됩니다.

1. 이전 실행기의 명령창을 닫고 최신 ZIP을 새 폴더에 풉니다.
2. `start-windows.cmd`를 실행합니다. 같은 브라우저와 `http://127.0.0.1:4173` 주소를 사용하면 기존 데이터가 유지됩니다.
3. 화면 오른쪽 위 **AI 연결**을 엽니다. 설치와 필요한 옵션을 확인하며 이 단계에서는 모델을 호출하지 않습니다.
4. 각 에이전트의 **응답 테스트**를 누릅니다. 실제로 완료된 응답이 와야 **응답 확인됨**으로 표시됩니다. 계정 사용량을 사용하는 요청입니다.
5. 프로젝트 → **기획 보드 → AI 기획 요청**에서 1~3개 에이전트를 선택하고 의견을 덧붙여 요청합니다.
6. 응답을 비교한 뒤 **선택한 응답 반영**을 누릅니다. 공통 제안은 기존 통합 규칙에 따라 하나의 노드로 합쳐지고 출처는 모두 남습니다. 요청 의견과 AI 검토는 대화에 저장됩니다.
7. 노드를 수정하거나 대화에 피드백을 저장하고 다시 요청하면 이전 에이전트들의 의견도 전달됩니다. 노드별 대화의 **AI에 검토 요청**으로 검토 범위를 지정할 수 있습니다.

하나가 실패해도 다른 에이전트의 응답을 반영할 수 있습니다. 요청 취소, 선택한 대기 시간 제한(기본 무제한), 응답 형식 검증, 같은 에이전트의 중복 실행 방지, 적용 전 미리보기를 지원합니다. 미반영 응답과 진행 중 요청 ID는 현재 탭 세션에 임시 보관됩니다. 새로고침 후 같은 프로젝트에서 AI 기획 요청을 열면 다시 확인할 수 있습니다. 브라우저 탭을 닫으면 임시 기록이 사라질 수 있으므로 중요한 응답은 먼저 반영하세요.

### 웹 대시보드에서 현재 PC 연결

1. PC 실행기를 먼저 켭니다.
2. 로컬 화면의 **AI 연결 → 웹 연결 코드 복사**를 누릅니다.
3. 웹 대시보드의 **AI 연결**에 `http://127.0.0.1:4173`과 연결 코드를 입력하고 연결 확인을 누릅니다.
4. Edge/Chrome이 로컬 네트워크 접근 권한을 요청하면 허용합니다. 브라우저나 회사 정책에서 차단하면 로컬 화면에서 사용할 수 있습니다. 웹과 로컬의 프로젝트 저장소는 별도이므로 내보내기/가져오기로 옮깁니다.

실행기를 재시작하면 연결 코드가 바뀝니다. 연결 코드는 API 키가 아니며 현재 실행기 세션의 접근 코드입니다. 코드와 로그인 정보는 프로젝트 백업에 넣지 않습니다. 회사·집에서 각각 실행기를 켜고 연결해야 합니다. 현재 버전은 같은 PC의 실행기에 연결하며, 꺼진 다른 PC를 원격 실행하지 않습니다.

### 연결되지 않을 때

- **CLI 설치 필요**: 위 버전 확인 명령이 PowerShell에서 동작하는지 확인하고 실행기를 재시작합니다.
- **업데이트 필요**: 설치는 되어 있으나 구조화 응답·기획 모드 등에 필요한 옵션이 없는 경우입니다. 공식 업데이트 후 다시 확인합니다.
- **설치 확인 · 테스트 전**: 실행 파일만 확인한 상태입니다. 로그인 완료 여부는 응답 테스트로 확인합니다.
- **로그인/사용량/조직 정책 오류**: PowerShell에서 해당 CLI를 직접 실행해 확인합니다. 대시보드에 인증 정보를 붙여넣지 않습니다.
- **실행기 접속 실패**: 명령창 실행 상태, 포트, 브라우저의 로컬 네트워크 권한을 확인합니다. 포트 변경은 PowerShell에서 `$env:PORT='4174'; npm start`로 할 수 있습니다. 다른 주소의 브라우저 저장소는 별도입니다.

표준 경로가 아닌 곳에 CLI가 설치됐다면 PowerShell에서 절대 실행 파일 경로를 설정한 후 같은 터미널에서 `npm start`를 실행합니다.

```powershell
$env:AGENT_DESK_CODEX_BIN = 'C:\Tools\codex.exe'
$env:AGENT_DESK_CLAUDE_BIN = 'C:\Users\사용자명\.local\bin\claude.exe'
$env:AGENT_DESK_AGY_BIN = Join-Path $env:LOCALAPPDATA 'agy\bin\agy.exe'
npm start
```

실제 설치 경로로 바꾸세요. `.exe` 또는 Node `.js`/`.mjs`/`.cjs` 엔트리 파일을 지원합니다. `.cmd`/`.bat`/`.ps1`을 에이전트 실행 파일로 사용하지 않습니다. npm으로 설치한 Codex·Claude의 표준 엔트리 파일은 자동 탐색합니다. 사용자 프롬프트는 셸 명령으로 조합하지 않고 stdin으로 전달합니다.

### 구현 범위와 검증

- 공식 비대화형 인터페이스 사용: Codex `exec`, Claude `-p`, AGY `stream-json` 입력과 출력.
- 공식 CLI가 관리하는 이 PC의 인증을 사용합니다. 브라우저가 OAuth 토큰이나 API 키를 읽지 않습니다. 연결은 새로운 CLI 기획 세션이며, 기존 데스크톱 대화 내용은 자동으로 가져오지 않습니다.
- 요청마다 임시 작업 폴더를 사용합니다. 기획 요청은 프로젝트 설명·공통 지침·현재 기획·저장된 의견을 보냅니다. 개발·검토 요청은 별도 작업본의 소스와 실제 검사 결과도 전달합니다. 프로젝트 첨부 파일은 자동으로 보내지 않습니다.
- Codex는 read-only 모드, Claude는 도구를 비활성화한 plan 모드, AGY는 plan 모드와 지원되는 경우 sandbox를 사용합니다. AGY의 OS 샌드박스 지원 여부와 CLI 자체 사용자/조직 설정은 설치 환경에 따릅니다. 개발·검토에서는 CLI 응답의 파일 변경을 실행기가 별도 작업본에 적용합니다.
- 서버는 loopback 주소에만 바인딩합니다. API는 loopback 접속·Host·Origin·세션 토큰을 검사하고 등록된 웹 대시보드 하나에만 CORS를 허용합니다.
- 프로세스 계약, 응답 파싱, 취소·시간 제한, API 접근 제어, UI 요청→미리보기→반영, 일부 에이전트 실패, 기존 저장 기능을 자동 검증합니다. 테스트용 CLI 프로세스를 사용하며 실제 유료 계정의 Windows 종단 간 테스트를 대신하지는 않습니다.
- v0.8.0에서는 Chromium으로 방안 선택·역할 저장·페이지 이동·실제 파일 생성·검사·프로그램 실행·ZIP 다운로드까지 확인했습니다. AI 응답은 테스트용 CLI를 사용했습니다.

공식 자동 호출 문서: [Codex](https://developers.openai.com/codex/noninteractive), [Claude Code](https://code.claude.com/docs/en/headless), [Antigravity](https://antigravity.google/docs/cli/headless/).

## 개발 및 검증

```sh
npm start
npm run check
npm ci --ignore-scripts --no-audit --no-fund
npm test
```

- `public/`: 빌드 없이 배포 가능한 웹 화면
- `public/model.js`: 프로젝트 형식 검증, 백업 검증, 가져오기 및 검색
- `public/planning.js`, `public/planning.css`: 노드 보드와 편집·대화·비교 화면
- `public/planning-model.js`: 그래프 검증·통합·이력·제안 가져오기
- `public/storage.js`: IndexedDB의 트랜잭션과 충돌 방지
- `scripts/serve.mjs`, `scripts/server.mjs`: 로컬 웹 서버와 폴더 선택 API
- `scripts/agent-*.mjs`: CLI 탐색·실행·요청 관리·연결 API
- `public/agent-client.js`, `public/agent-ui.js`: 연결 설정과 실제 기획 요청 화면
- `scripts/folder-picker.mjs`: Windows 폴더 선택창 (고정 PowerShell 스크립트)
- `tests/`: 현재 PC 경로·Git 주소, 첨부 보존, 가져오기, 저장소 마이그레이션·삭제, 폴더 선택 API 검증

위 설치 명령은 테스트용 개발 의존성을 준비할 때만 필요합니다. 현재 잠금 파일의 `decimal.js@10.7.0`을 공식 저장소에서 찾지 못하므로, 잠금 파일을 바꾸지 않는 설치 옵션을 사용합니다. 일반 실행에는 추가 패키지가 필요하지 않습니다.

공통 폰트는 Google Fonts에서 불러오며, 인터넷 연결이 없으면 시스템 글꼴을 사용합니다.
