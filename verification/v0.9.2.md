# v0.9.2 통합 요청 용량과 실패 복구 검증

사용자 화면의 **“요청 내용을 확인해 주세요.”**는 v0.9.1 실행기의 일반 요청 검증 문구였습니다. 실제 사용자 응답 원문은 없으므로 그 요청의 크기를 직접 측정한 것은 아닙니다. 긴 응답을 합칠 때 동일한 오류가 발생하는 경로를 코드와 재현 데이터로 확인했습니다.

2026-11-14(한국 시간): 전체 자동 테스트 **210개 통과, 실패 0개**, 애플리케이션·실행기 구문 검사와 `git diff --check` 통과.

## 재현과 복구

실제 Chromium에서 v0.9.1 서버와 v0.9.2 서버를 실행하고 26개 노드·세 AI의 긴 독립 검토 응답을 사용했습니다. 실제 AI 계정 대신 테스트용 CLI 프로세스를 사용했습니다.

1. v0.9.1에 보관된 세 응답으로 통합 요청: 약 26만 자로 기존 15만 자 제한 초과. **“요청 내용을 확인해 주세요.”** 오류를 재현했고 주 AI 작업 ID는 생성되지 않았습니다.
2. 동일한 프로젝트·응답·실패 상태를 v0.9.2에 복원. 독립 검토를 자동 재요청하지 않고 위쪽에 통합 재시도 버튼을 표시했습니다.
3. **기존 응답으로 주 AI 통합 재시도** 한 번으로 `organize-merge` 요청 **1회**만 전송했습니다. 요청은 **251,325자**였고 원문을 자르지 않았습니다.
4. 통합안 반영 후 창 닫힘·새로고침 후 저장 유지·AI 원문 세 개의 전체 내용 보존을 확인했습니다. 페이지 JavaScript 오류와 모바일 가로 넘침은 없었습니다.

별도 HTTP/CLI 통합 테스트에서는 **288,765자**, JSON 전송량 약 **657KB**의 한글 통합 요청을 처리해, 기존 600KB 전송 제한도 함께 해결했음을 확인했습니다. 한도 초과 요청은 크기·한도를 포함한 오류로 거절됐으며 추가 CLI 호출은 없었습니다.

## 회귀 검사

- `tests/review-capacity.test.mjs`: 긴 노드·세 응답의 모든 요구사항 보존, 과거 AI 설명과 이력의 반복 전송 제거, 사용자 답변·선택지 보존, 실제 HTTP 바이트 한도·CLI 전달 및 초과 요청의 호출 전 차단.
- `tests/lead-review-ui.test.mjs`: 실패 상태 복원, 기존 응답 재사용, 통합만 재시도, 잘못된 결과의 반영 차단, 자동 재시도 반복 없음.
- 기존 기본값·계층·질문 중복·취소·개발·실행·다운로드 검사도 함께 실행합니다.
