# v0.9.5 노드 정리의 목표 중복·ID 충돌 검증

2026-11-14(한국 시간): 전체 자동 테스트 **230개 통과, 실패 0개**, `npm run check`와 `git diff --check` 통과.

## 관찰과 원인

사용자 화면의 오류는 정리안 노드의 임시 ID가 선택 범위 밖의 기존 노드 ID와 겹칠 때 발생합니다. 화면에 펼친 독립 응답에는 기존 목표와 같은 제목의 노드 및 “선택하지 않은 전체 목표를 유지하고 정리안에도 포함합니다”라는 이유가 보였습니다. 실제 최종 통합 JSON 전체는 확보하지 않았으므로 사용자의 모든 충돌 ID를 직접 확인한 것은 아닙니다.

기존 지시문은 목표를 유지하라고 했지만 응답에서 제외하라는 뜻을 명시하지 않았습니다. 기존 코드는 충돌을 일괄 거절했고, v0.9.4의 한 번 자동 정정은 질문 검토에만 연결돼 있었습니다.

## 변경과 보호 조건

- 기존 목표 ID를 가진 최상위 복사본이 새 실행 작업·요구·선행 관계를 포함하지 않고 내용이 원래 목표와 같거나 비어 있을 때만 제거합니다. 그 자식의 최상위 연결은 기존 목표로 이어집니다. 원본 목표 내용은 유지됩니다.
- 단순한 임시 ID 충돌은 다른 기획 ID·응답 ID·선행 참조와 겹치지 않는 키로 바꾸고 `parentId`도 함께 바꿉니다. `sourceIds`, `derivedFrom`, 선택하지 않은 실제 노드 ID, 원래 작업에서 상속한 외부 의존성은 그대로 유지합니다.
- 충돌 ID를 `dependsOn`에서도 명시적으로 사용하면 응답 내부 작업과 외부 기존 작업 중 어느 쪽인지 추측하지 않습니다. 구체적인 충돌 ID와 앞선 정리안을 주 AI에게 보내 최대 1회 정정합니다. 목표에 추가된 요구도 버리지 않고 정정을 요청합니다.
- 정정은 `organize-merge` 종류로 요청합니다. 독립 검토를 반복하지 않으며 실패한 정정을 새로고침만으로 재호출하지 않습니다. 기존 질문 정정·취소·복구 동작도 유지합니다.
- 미리보기와 적용 모두 동일한 정규화·검증을 사용합니다. 선택 노드 누락·중복·범위 밖 제외·실행 순환 등 실제 구조 오류의 검사는 제거하지 않았습니다.

## 자동 검사

- `tests/organize-order.test.mjs`: 목표 복사본의 빈 `sourceIds` 및 목표 ID 포함 형태, 목표 보존과 자식 계층·선행 관계 유지, 임시 ID 변경 시 부모 참조 일관성, 외부 의존성 유지, 원본 비변경, 모호한 연결·목표 내용 변경 차단.
- `tests/organize-recovery-ui.test.mjs`: 보관된 목표 충돌의 AI 호출 없는 복구·미리보기·적용, 사용자 RAD 답변과 독립 원문 보존, 모호한 충돌의 `organize-merge` 정정 1회, 정정 실패·재개 시 반복 없음.
- 기존 전체 자동 진행·질문 통합·노드 계층·취소·진행 표시·개발·Windows 패키지 검사를 포함해 230개를 통과했습니다.

## 실제 Chromium 재현

동일한 테스트용 프로젝트와 AI 응답을 v0.9.4 서버 및 v0.9.5 서버에 넣었습니다. 목표 복사본과 두 선택 작업, 선택하지 않은 별도 작업, 기존 RAD 사용자 답변을 포함했습니다.

1. v0.9.4: **“정리안 ID가 선택 범위 밖의 노드 ID와 겹칩니다.”**를 재현했고 반영 버튼이 없었습니다.
2. 같은 실패 상태와 응답을 v0.9.5로 복원: 추가 AI 요청 **0회**, 목표 중복 복구 안내와 **2개 선택 → 2개로 정리**, 반영 가능한 미리보기를 확인했습니다.
3. 반영 후 새로고침: 목표는 1개이고 기존 제목·설명을 유지했습니다. 선택하지 않은 작업과 RAD 답변 및 세 독립 응답 원문도 보존했습니다. 페이지 JavaScript 오류는 없었습니다.

화면: [이전 오류 재현](organization-root-old-error.png), [동일 응답 자동 복구](organization-root-restored.png).

Windows 실기기·실제 공급자 응답 품질은 검증하지 않았습니다. 이 수정은 임시 ID와 기존 노드 참조의 처리 문제를 해결하며, 모호한 의미·추가 요구·잘못된 실행 의존성까지 임의로 성공 처리하지 않습니다.
