# v0.9.3 실제 진행 상태와 연결 지연 검증

2026-11-14(한국 시간): 전체 자동 테스트 **216개 통과, 실패 0개**, `npm run check`와 `git diff --check` 통과.

## 관찰 범위

기존 UI의 “주 AI가 통합 중”은 요청이 완료되지 않았다는 표시이며, 사용자 스크린샷만으로 실제 생성 여부를 확인할 수 없었습니다. Claude만 파싱하던 실행 중 이벤트를 Codex와 Antigravity에도 적용하고, 세 CLI 모두 프로세스 시작·종료와 stdout/stderr 수신량·시각을 별도로 수집했습니다. 텍스트와 내부 추론을 진행 정보로 전달하지 않습니다.

브라우저가 응답을 받은 시각과 서버가 계산한 경과·무출력 시간을 사용해 서버/브라우저 시계 차이의 영향을 줄였습니다. 출력과 연결 확인은 별개이며, UI 타이머가 가짜 출력 이벤트를 만들지 않습니다. 연결 확인 지연 10초와 무출력 2분은 안내 기준일 뿐 실패·취소·자동 재요청 조건이 아닙니다. 실제 완료율이나 남은 시간은 표시하지 않습니다.

## 자동 테스트

- `tests/agent-progress.test.mjs`: 세 CLI의 조각난 이벤트 파싱, 사적인 출력 비노출, 실제 테스트용 자식 프로세스의 실행·출력·취소 관찰, 조회만으로는 출력 시각·수신량이 늘지 않음, 완료 후 경과 시간 고정.
- 같은 테스트에서 시간을 주입해 2분 무출력·10초 연결 지연·최근 출력·결과 정리·실패 연결 상태를 구분합니다. 오랫동안 조용한 프로세스를 중단됐다고 단정하지 않습니다.
- `tests/lead-review-ui.test.mjs`: 접지 않아도 보이는 상태, 참여 AI별/주 AI별 표시, 타이머가 입력과 버튼을 교체하지 않음, 조회 중 펼친 상세 정보 유지. 기존 자동 통합·응답 복원·재시도·반영 검증도 유지합니다.
- 전체 216개 검사에는 기존 취소·시간 제한·질문 기본값·노드 계층·긴 통합 요청·개발·다운로드 회귀 검사가 포함됩니다.

## 실제 Chromium 검증

테스트용 CLI를 사용하는 로컬 HTTP 서버와 26개 노드·보관된 세 독립 응답으로 실행했습니다. 통합용 CLI는 이벤트를 출력한 뒤 취소될 때까지 조용히 실행되도록 구성했습니다.

1. 주 AI 통합 **1회** 요청 후 접힌 메뉴 밖에서 프로세스 실행, 연결 정상, 최근 출력과 경과 시간을 확인했습니다.
2. 경과 시간은 늘지만 새 출력이 없는 동안 서버의 출력 시각·수신량은 변하지 않았습니다. 내부 추론과 테스트용 비공개 표식은 API 진행 정보에 없었습니다.
3. 실제 상태 조회 요청을 보류하자 10초 후 **현재 상태 미확인** 및 연결 확인 지연으로 표시됐습니다. 그 요청을 네트워크 오류로 종료한 뒤 **상태 다시 확인**으로 같은 작업을 조회했습니다. 추가 AI 요청은 없었습니다.
4. **요청 취소** 후 취소 상태를 저장했고 독립 응답 세 개는 그대로 보존됐습니다.
5. 상세 정보 펼침 유지, 모바일 가로 넘침 없음, 페이지 JavaScript 오류 없음도 확인했습니다.

실제 모델의 내부 작업 상태·응답 품질·Windows 실기기 실행은 검증하지 않았습니다. 프로세스가 살아 있고 실행기 연결이 정상이어도 모델 내부의 정지 여부를 단정할 수 없습니다. 현재 진행 중인 사용자 요청을 중단할 필요 없이 기다릴 수 있으며, 서버 교체는 완료 또는 사용자가 선택한 취소 뒤에 해야 합니다.
