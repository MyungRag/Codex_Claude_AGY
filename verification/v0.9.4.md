# v0.9.4 질문 통합의 연결 오류 자동 정정 검증

2026-11-14(한국 시간). 기존 223개 전체 테스트 통과 후 저장 공간 부족 시 추가 호출 차단 검사를 추가했으며, 해당 파일의 6개 검사를 모두 통과했습니다. 총 **224개 통과**, 구문 검사와 `git diff --check` 통과.

## 원인과 수정 범위

스크린샷의 오류는 주 AI 응답의 `existingIds`가 검토 범위의 기존 질문 ID와 정확히 한 번씩 대응하지 않을 때 발생했습니다. 이 조건에는 누락·중복뿐 아니라 알 수 없는 ID도 포함됐으나 이전 문구에서는 구분하지 않았습니다. 사용자의 실제 응답 JSON은 없어 어떤 ID가 문제였는지까지 확인한 것은 아닙니다.

기존 흐름은 결과를 검증하고 멈춘 뒤 같은 통합 요청의 수동 재시도만 제공했습니다. 이번 변경은 데이터 보존 검사를 제거하지 않고 다음 복구를 추가합니다.

1. 한 항목 안의 반복 연결을 정리하고, 질문 종류·내용·노드가 정확히 일치하는 단일 후보의 빠진 기존 ID만 복원합니다. 다른 문장이나 모호한 후보는 추측해서 연결하지 않습니다.
2. 검증 실패 시 누락·중복·알 수 없는 ID 또는 제안 출처의 구체적인 목록을 생성합니다. 최초 통합 프롬프트에도 필수 기존 ID 목록을 명시합니다.
3. 기존 기획·독립 응답·잘못된 통합안·검사 결과를 주 AI에 전달해 최대 1회 자동 정정합니다. 정정 시도를 보내기 전에 횟수를 저장하며, 저장 실패 시 호출하지 않습니다.
4. 자동 정정에도 실패하면 원문을 보존하고 중단합니다. 새로고침은 횟수를 초기화하지 않으며 취소를 자동 재시작하지 않습니다. 사용자가 명시적으로 새 통합을 요청한 경우에만 새 시도를 시작합니다.

## 자동 검사

- `tests/lead-review.test.mjs`: 정확한 연결 복원과 중복 정리, 원본 비변경, 사용자 답변 유지, 모호한 중복 연결 차단, 구체적인 오류 목록과 정정 프롬프트. 기존 서로 다른 답변·보류·노드·대화 출처 보호 검사도 유지했습니다.
- `tests/review-repair-ui.test.mjs`: 시작 한 번으로 자동 정정과 반영까지 연결, 기존 실패 상태 복원, 코드만으로 복원할 때 AI 호출 없음, 실패 시 정정 1회 제한, 재개·취소·연결 복구, 저장 공간 부족 시 호출 차단.
- 나머지 진행 표시·취소·시간 제한·긴 요청·개발·다운로드 회귀 검사를 포함해 총 224개를 확인했습니다.

## 실제 Chromium과 로컬 HTTP/CLI 검사

테스트용 CLI가 첫 통합에서 기존 질문 ID를 누락하고 문장도 바꿔 자동 연결로 처리할 수 없는 결과를 반환하도록 설정했습니다. 정정 요청에서는 유효한 결과를 반환했습니다.

- 검토 시작 버튼 **1회**: 독립 검토 **3회**, 최초 통합 **1회**, 자동 정정 **1회**.
- 자동 정정 중 브라우저 새로고침 후 같은 검토 창을 열어 기존 요청 ID로 이어갔으며 추가 AI 요청은 없었습니다.
- **통합안 반영** 후 창 닫힘과 새로고침 후 저장 유지를 확인했습니다. 기존 질문 ID와 사용자가 선택한 **RAD**를 유지했고, AI 추천 **DEG**로 덮어쓰지 않았습니다. 질문 개수는 1개로 유지됐고 세 독립 응답 원문을 보존했습니다.
- 페이지 JavaScript 오류는 없었습니다.

화면: [자동 정정 중](question-repair-running.png), [정정·검증 완료](question-repair-ready.png).

이 검증은 실제 공급자 계정이나 Windows 실기기를 사용하지 않았습니다. AI가 항상 올바른 수정안을 낸다는 보장은 없으며, 통합의 의미 오류·외부 사실·인증·통신 오류를 성공으로 간주하지 않습니다. 추가 정정 요청에도 기존 크기 한도와 취소 정책이 적용됩니다.
