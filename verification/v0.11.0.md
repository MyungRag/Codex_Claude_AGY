# v0.11.0 검증 기록

2026-11-14. 변경 전 기준: `303a41eb2ce7ceb66fbd172017739fa7e696e4ef`. 브랜치: `codex/fix-decision-review-apply`.

## 변경 범위

- 초기 기획에서 단일 AI 또는 참여 AI와 주 AI 선택. 단일 선택은 초안 1회, 복수 선택은 주 AI 초안 → 다른 AI의 동일 초안 병렬 검토 → 주 AI의 선별 반영.
- 실행 가능한 핵심 범위, 추천 기본값·대안·이유, 선택 기능의 후속 보관. 필수 요구를 미루는 경우 별도 사용자 확인.
- 포함 관계에 따른 자연스러운 계층. 깊이·노드 수를 강제하지 않고 주요 기능부터 표시. 펼치기와 수동 위치 이동 유지.
- 후속 후보의 선택적 기획 편입. 관련 위치·선행 작업을 검토해 미리보기 후 반영. 기존 답변 보존, 새 노드만 질문 검토 대상으로 추가.
- 개발 참여 AI 선택, 기본 통합안의 구현 담당 분산, 빈자리마다 다음 독립 작업을 시작하는 연속 스케줄러.
- 작업별 대기 한도와 선택 작업만 보류. 구현 요청 실패 시 다른 참여 개발자에게 최대 1회 재배정. 독립 작업·최종 초안 통합 계속 진행.
- 전체 실행 후보 검사를 구현 대기열 뒤로 이동. 전체 검사 호출 실패를 기록하고 초안 통합 시도를 계속함. 실제 핵심 검사 실패는 여전히 새 실행 버전을 차단.
- 기존 AI 실행 확인의 두 세부 탭에 새 기획 단계·담당 AI·작업별 대기 이유 표시. 모니터 이동 후 돌아왔을 때 요청 중복 방지.

## 자동 검사

- `npm test`: **260개 통과**.
- `npm run check`: 애플리케이션·실행기 모듈 구문 검사 통과.
- `git diff --check`: 공백 오류 없음.

주요 회귀 검사:

- 단일 AI의 1회 호출과 저장 실패 시 수정한 기본값·응답 보존.
- 두 검토자가 같은 초안을 병렬 검토한 후 주 AI가 정리하며, 부분 검토 실패 시 성공한 의견과 초안을 보존.
- 모니터 이동·복귀 시 진행 중 요청을 재사용.
- 단순 기능 한 노드와 자연스러운 중첩 계층 모두 허용. 순환·잘못된 연결은 반영하지 않음.
- 동일 결과 재반영 시 노드·가정·후속 후보가 누적되지 않음. 백업 왕복·되돌리기·다시 실행 보존.
- 후속 후보는 현재 업무 분담에서 제외. 선택한 후보만 편입하며 기존 답변을 유지하고 새 노드만 질문 대상이 됨.
- 두 작업 중 하나가 대기해도 다른 작업이 끝나는 즉시 세 번째 독립 작업 시작.
- 기본 통합안에서도 선택한 여러 개발 AI에 작업 분산.
- 작업별 보류 시 다른 작업과 최종 초안 통합 계속. 마지막 통합 검토에서도 보류 이유 보존.
- 전체 검사 예외가 초안 통합을 건너뛰지 않음. 실제 핵심 검사 실패는 통과로 바꾸지 않음.
- 작업별 보류 API의 연결 인증·출처·요청 본문 전달 확인.

진행 중 요청을 완료하거나 취소하고 기존 명령창에서 `Ctrl+C`를 누른 뒤, 새 ZIP을 별도 폴더에 풀어 `start-windows.cmd`로 실행하세요. 기존 브라우저의 같은 `http://127.0.0.1:4173` 탭에서 `Ctrl+Shift+R`을 누릅니다. 프로젝트·브라우저 데이터·사용자 홈의 `.agent-desk` 폴더를 삭제할 필요가 없습니다.

실제 Codex·Claude·Antigravity 응답 품질, 외부 서비스 연결, Windows 실기기 실행은 이번 검증에 포함하지 않습니다. 기본값이나 후속 분리 판단이 항상 옳다고 보장하지 않으며 사용자가 미리보기에서 확인합니다. 핵심 실행 오류까지 무시하고 완성품으로 표시하지 않습니다. 결과물의 선택지를 변경해 자동으로 재개발하는 전용 수정안 개발 화면은 이번 범위 밖입니다.
