# v0.12.0 검증 기록

검증일: 2026-11-14. Linux / Node.js 24 / 실제 headless Chromium. 실제 유료 AI 호출 대신 결정적인 CLI 응답 fixture를 사용했습니다.

## 확인 결과

- `npm test`: **276개 통과, 실패·건너뜀 0**.
- `npm run check`: 애플리케이션·실행기 모듈 구문 검사 통과.
- `node verification/v0.12.0-browser.mjs`: 실제 HTTP 서버, CLI 프로세스, 개발 실행기, Chromium UI를 연결한 검증. 초기 기획·후속 편입 각각 독립 기획 3회 + 주 AI 통합 1회. 계산기 작업 3개를 완료하고 단위·화면 검사 8개 통과, 브라우저 예외 0건.
- 추가로 고의로 실패하는 호스트 검사를 넣어 재실행했습니다. 실패 판정은 유지하면서 시작 가능한 새 초안을 미리보기·실행·ZIP으로 제공하고, 이전 정상 실행 버전도 선택할 수 있음을 확인했습니다.

## 주요 회귀 검증

1. 깊은 그룹 아래 독립 구성도 서로 다른 AI에서 동시에 시작합니다. 같은 AI의 요청은 겹치지 않고, 파일 충돌은 최신 소스에 대해 다시 구현합니다. 빈 실행 자리는 다른 느린 작업을 기다리지 않습니다.
2. `integrationWith`는 후속 연결을 위한 관계이며 시작 조건 `dependsOn`으로 바뀌지 않습니다. ID 재매핑, 기획 정리 중 그룹→자식 연결, 저장·확정·업무 분담, 명시적 관계 제거를 검증했습니다. 구버전 데이터도 로드합니다.
3. 필요한 계약이 실제로 준비되었다는 검토 근거가 있으면 관계없는 미결정 때문에 소비 작업을 막지 않습니다. 준비되지 않은 계약은 해당 의존 작업만 차단합니다. 미결정과 구현 오류가 함께 있어도 구현 오류 수정을 시도합니다.
4. 전체 초안을 최대 3회 구현하고 개발 AI를 바꿔가며 이전 코드·검사 실패를 전달합니다. 시작 오류도 복구 AI에 전달합니다. HTTP 응답만 있고 기능 근거가 부족하면 남은 복구 시도를 이어갑니다. 사용자의 작업 보류·취소는 다시 시작하지 않습니다.
5. 실패한 검사와 원래 노드 판정을 통과로 바꾸지 않습니다. 시작 가능한 초안만 실행 가능으로 게시하고, 실패한 시작은 게시하지 않습니다. 통합 감사의 기능별 결과는 코드 버전과 연결하며 존재하지 않는 검사 ID를 검증 근거로 인정하지 않습니다.
6. 기획도에서 실제 개발·검토·Challenger AI와 완료·일부 구현·미개발 상태를 표시합니다. 진행 상태만 갱신하며 전체 캔버스를 다시 만들지 않습니다. 마지막 분석 이후 잘못 남는 ‘분석 중’ 표시를 제거했습니다.
7. 초안 기획에서 선택한 AI 3개가 모두 동시에 시작한 후 주 AI만 통합합니다. 한 AI 선택은 한 요청입니다. 모니터 이동·복귀로 호출이 중복되지 않고, 성공한 응답은 보관됩니다. 요청 카드에는 연결 확인 시각과 실제 출력 신호를 표시하고 완료·실패·취소를 유지합니다.
8. 실제 Chromium에서 첫 검사가 로컬 저장소·쿠키를 변경해도 다음 검사는 깨끗한 상태로 시작합니다. 추가 `integration.test.mjs`의 실패도 자동 검사에 반영됩니다.
9. 실행 중인 미리보기는 유지하면서 새 초안 알림과 버전 목록을 갱신합니다. 저장된 초안을 선택하여 실행·다운로드하고, 미구현·검사 실패를 기능별로 확인합니다. 390px 화면에서 페이지 전체의 가로 넘침이 없습니다.

## 확인 범위

사용자가 보낸 KAF JSON은 실행 기록이며 프로그램 소스가 포함되어 있지 않습니다. 사용자의 KAF 자체를 여기서 재실행하거나 완성했다고 주장하지 않습니다. 실제 AI 응답 품질, 외부 항공 서비스 연동, Windows 실기기·로그인한 CLI는 이번 자동 검증 대상이 아닙니다. 새 버전은 초안 생성·복구·표시 흐름을 고치지만 어떤 프로그램이든 반드시 완성된다는 보장은 하지 않습니다. 기본 복구 한도는 3회입니다.
